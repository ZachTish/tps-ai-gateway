# TPS AI Gateway 0.2.4

## Intent

Reduce repeated provider-preparation work while preserving every released transport, fallback, queue, settings, and public API behavior.

## Changes

- Partition system instructions and conversational messages once per provider attempt through one internal helper.
- Reuse that partition for Ollama grounding, OpenAI instructions/input, and Gemini system/content payloads.
- Remove the second full-array role-classification pass from all three provider adapters.
- Add no cache, persisted state, retry, alternate provider route, monkeypatch, polling, or unsupported Obsidian behavior.

## Before/after evidence

- The focused provider request-shape regression passed against the exact `0.2.3` source before the runtime edit and passed unchanged afterward.
- Actual `0.2.3` and candidate modules matched across 75,021 provider calls over 25,007 explicit and seeded message arrays. The corpus covered empty, all-system, no-system, interleaved, empty-content, Unicode, NUL, frozen, and sparse inputs.
- Request options, serialized bodies, response extraction, returned model/text values, thrown configuration errors, input order, and input immutability had zero supported-input mismatches.
- Each provider now classifies the complete message list once instead of twice. With 100,000 messages, classification checks fall deterministically from 200,000 to 100,000, while total observable role reads fall from 266,666 to 166,666 and content reads remain 100,000.
- Across 31 interleaved large-array provider-boundary rounds, medians changed from 15.806 ms to 15.157 ms for Ollama, 15.923 ms to 14.459 ms for OpenAI, and 21.512 ms to 19.668 ms for Gemini—improvements of 4.1%, 9.2%, and 8.6%, respectively.
- The final production bundle shrinks from 25,714 to 25,662 bytes despite the shared explicit helper.

These checks use a local `requestUrl` stub. No provider credential was read and no live Ollama, OpenAI, or Gemini request was sent. Network and model latency are intentionally outside this CPU-only optimization claim.

## Validation

- Exact public `0.2.3` was pinned at commit `b830a04503800a82ad33855072fd0cf34348d62e`.
- The untouched baseline passed all 24 declared tests, TypeScript, and its production build with runtime deployment suppressed.
- The final versioned release tree passes all 25 provider, gateway, persistence, privacy, queue, and settings tests, TypeScript, and the mandatory separate production-mode build.
- The final artifacts deploy byte-identically only to the registered Obsidian Plugin Test Vault.
- Obsidian 1.12.7 retains the provider-chain command without invoking it or issuing an outbound request.
- Runtime-owned `data.json` remains byte-identical. Production was not accessed.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- Provider ordering, intentional provider fallback, per-attempt timeout, credentials, models, schema enforcement, request payloads, response parsing, queue format, notification behavior, settings, and public APIs are unchanged.
- No settings, credentials, queue, or data migration is required.
- `AiMessage[]` remains a plain-data transport contract. Behavior that depends on stateful property getters, traversal-mutating proxies, or overridden array methods is not supported and is no longer coupled to repeated classification reads.
- The gain affects local provider-payload preparation; it does not claim a measurable reduction in end-to-end model latency for ordinary small message lists.
