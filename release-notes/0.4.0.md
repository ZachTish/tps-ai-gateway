# TPS AI Gateway 0.4.0

## What changed

- Added optional Gemini `google-search` grounding to `completeStructured()`.
- Implemented grounding as a bounded evidence request followed by a separate JSON-schema extraction request, retaining compatibility with the configured Gemini 2.5 Flash default.
- Returned a bounded, deduplicated list of actual HTTP(S) grounding sources and marked retrieved content as untrusted data during extraction.
- Kept grounded work Gemini-only and text-only, with exact durable-request matching and synchronized result recovery.
- Added `api.features.googleSearchGrounding` so domain plugins can reject older Gateway versions instead of silently running ungrounded.
- Fixed newly submitted durable jobs to persist their durable marker, preserving completed-result resume after sync or app restart.

## Compatibility and privacy

- Backward-compatible public API extension; no settings or queue migration is required.
- Provider credentials remain device-local in SecretStorage. Grounded prompts/results use the existing durable queue only when the requesting device cannot execute locally; inline images remain prohibited from that queue.
- Minimum supported Obsidian version: 1.12.0.

## Validation

- All 29 Gateway checks passed, including Google Search tool shape, separate schema extraction, source filtering, Gemini-only routing, image rejection, exact durable matching, and completed-result recovery.
- The required final production-mode build deployed only to the isolated test runtime. Health 0.11.0 feature-detected the loaded grounding contract and rendered its wider-search path. The isolated vault did not change a credential or send a grounded provider request.
- Production was not accessed or deployed.
