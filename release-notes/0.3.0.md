# TPS AI Gateway 0.3.0

TPS AI Gateway 0.3.0 adds safe device-local cloud execution and guarded Gemini image input for workflows such as TPS Health Nutrition Facts scanning.

## User-visible changes

- User-role devices now use their own configured OpenAI or Gemini SecretStorage credential for structured text requests before falling back to the Controller queue.
- Structured callers may attach up to three inline JPEG, PNG, or WebP images when explicitly selecting Gemini.
- Image requests never enter the synced Markdown Controller queue. A device without local Gemini receives an actionable error instead of persisting image data.
- Gemini receives image data and the existing strict JSON response schema in one native `generateContent` request.

## Safety and compatibility

- Inline media must be raw base64 without a data-URL prefix and is capped at 16 MiB encoded across at most three images.
- Ollama and OpenAI reject image-bearing requests rather than discarding their media.
- Prompts, images, schemas, responses, credentials, and caller metadata remain excluded from diagnostics.
- Existing text-only callers and existing Controller queue files remain compatible. No settings or data migration is required.
- Minimum supported Obsidian version: 1.12.0.

## Validation

- 26 gateway tests passed, covering Gemini media request shape, schema output, unsupported-provider rejection, media validation, device-local routing, text queue fallback, image no-queue behavior, provider safety, settings, and queue reliability.
- TypeScript no-emit validation and the required production build passed and deployed only to the isolated test vault.
- Obsidian 1.13.7 reloaded the isolated test vault and displayed the revised Gemini device-local text/image setting. The test vault intentionally has no linked Gemini secret, so no live model request or credential mutation occurred.
- The required separate build was byte-stable; source and test-runtime artifacts were byte-identical.
