# TPS AI Gateway 0.2.1

## Intent

Make Controller-side remote queue scanning reliable under overlapping Obsidian Sync and vault file events without introducing concurrent provider work or an unbounded rescan loop.

## Changes

- Preserve queue changes received while a scan is active by coalescing them into one serialized trailing pass.
- Cap each active scan epoch at the initial pass plus one trailing pass. Work raised during that trailing pass returns to the existing 750 ms debounce.
- Recheck Controller authority before the trailing pass.
- Keep maximum queue-read concurrency at one.
- Preserve every released provider, provider order and supported fallback, queue format, notification, setting, public API, and data contract. No migration is required.

## Before/after evidence

- A focused regression run against the released 0.2.0 implementation failed because 100 overlapping scan requests produced only the original folder snapshot and did not observe a newly arrived queue file.
- Version 0.2.1 coalesced the same burst into exactly one trailing snapshot and observed the new file.
- An adversarial request raised during the trailing pass did not create a third immediate snapshot; it was handed to the existing scheduler.
- Maximum concurrent reads remained one, and losing Controller authority before the requested trailing pass kept the scan at one snapshot.

## Validation

- Focused remote-queue concurrency tests: 3 passed.
- Full declared suite: 19 passed.
- Required separate production-mode build: passed and deployed only to the registered Obsidian Plugin Test Vault.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**. Cloud providers, Local Ollama, and Diagnostics settings destinations rendered without changing settings, linking credentials, or sending a provider request.
- Runtime `data.json` remained byte-identical at SHA-256 `6cfa72987ad1b642a8368b6c342a0b22d39fcab83af988b13e77c9398baee42b`.
- Production was not accessed or modified.

## Compatibility and limitations

- Minimum Obsidian version: 1.12.0.
- Remote jobs still rely on ordinary vault sync and retain the existing polling, claim-recovery, timeout, and retention limits.
- An already-running scan may finish during plugin unload; this is pre-existing behavior. New scan requests are cleared on unload.
- Provider fallback is intentional public behavior and remains unchanged.
