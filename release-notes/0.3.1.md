# TPS AI Gateway 0.3.1

## What changed

- Added caller-owned durable IDs for structured text requests. A durable request is stored before inference and can return its already-validated result after the requesting app restarts.
- Expanded queue workers beyond the TPS Controller: any synced device with a matching local Gemini/OpenAI credential can recover durable work. The requester receives the first claim window and other workers use a deterministic stagger.
- Durable ID collisions fail closed unless task, messages, schema, provider preference, and metadata all match exactly.
- Kept Nutrition Facts and every other inline-image request device-local; image bytes are never written into the vault queue.

## Compatibility and privacy

- Backward-compatible patch; no settings or queue migration is required.
- Durable text prompts and schemas use the existing `_assets/TPS AI Queue` sync path and 48-hour retention. Provider credentials remain device-local in SecretStorage, and prompts/results remain absent from diagnostics.
- Minimum supported Obsidian version: 1.12.0.

## Validation

- All 28 gateway checks passed, including completed-result resume, incompatible durable-ID rejection, requester-first recovery, abandoned-work recovery, exact Gemini worker routing, image no-queue guards, queue isolation, and the existing settings/provider regressions.
- The mandatory separate production-mode build passed and reported the final test runtime unchanged after deployment. Obsidian 1.13.7 was reloaded in the isolated test vault; Health's Describe tab registered and opened without changing a note, credential, or provider setting. The vault intentionally has no Gemini secret, so no live provider request was sent.
- Source and test-runtime release artifacts were byte-identical. Production plugin files were not inspected or deployed.
